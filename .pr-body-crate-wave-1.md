## What is in it

**The cutover front door** (`crates/star-proxy`) — the port answers the routes it owns, and the Canvas routes it does not own yet go to the Canvas instance the deployment still runs. `star-http` wires it into axum's fallback *and* axum's method-not-allowed fallback, because Canvas answers an undefined method with 404, never 405. `STAR_CANVAS_ORIGIN` turns it on; with no origin the front door is the empty 404 axum would answer anyway, so the recorded corpus still measures the port and nothing else.

**The byte store** (`crates/star-storage`) — Canvas' file-system backend: the partitioned attachment key, the local disk backend and the S3 backend behind one async trait.

**The background worker** (`crates/star-worker`) — the delayed_job worker: the handler registry, the claim loop, the V2 job API.

**The permission layer** (`crates/star-permissions`) — the rules, the registry and the contextual checks. The registry now covers all 160 Canvas permissions.

**The GraphQL root** (`crates/star-graphql`) — the query root fields, the node lookup, the root types.

**The schemas the port still owed** — accounts, enrollments, users and folders, courses and groups, and the access token's `crypted_token`.

**The LTI status diffs** — nine recorded answers that were wrong: the port answered 403 where Canvas answered 404, because it deleted the enrollment where Canvas concludes it.
